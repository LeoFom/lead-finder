# План розгортання на Render

Фази 0–1 готують незалежні команди збірки й запуску для сервісів. Створення Blueprint, виділення ресурсів, налаштування домену, секретів і перевірка відновлення у production належать до фази 14.

| Ресурс | Тип і команда з кореня monorepo | Конфігурація |
| --- | --- | --- |
| Web | Web Service, `pnpm --filter @lead-finder/web build`, потім `pnpm --filter @lead-finder/web start` | Next.js SSR, порт із середовища. Публічні URL містять лише публічні значення. |
| API | Web Service, `pnpm --filter @lead-finder/api... build`, потім `pnpm --filter @lead-finder/api start` | Nest слухає 0.0.0.0 і PORT. Секрети сесії та DATABASE_URL доступні на сервері. |
| Worker | Background Worker, `pnpm --filter @lead-finder/worker... build`, потім `pnpm --filter @lead-finder/worker start` | Окремий процес без HTTP-порту. У фазі 5 споживає чергу, зберігає checkpoint перед завершенням. |
| DB | Постійна керована PostgreSQL у регіоні API та worker | Внутрішнє підключення, обмежений доступ, секрет у Render, TLS відповідно до типу з’єднання. |
| Експорти | Streaming attachment або тимчасове об’єктне сховище | Метадані в БД, TTL і перевірка прав на скачування. |

Для кожного сервісу робоча директорія збірки — корінь. Перед його командою виконати `pnpm install --frozen-lockfile` з devDependencies для TypeScript. Версії Node та pnpm беруться з `.node-version` і `packageManager`. До розгортання зафіксувати `pnpm-lock.yaml` з перевіреної збірки. Для альтернативного Static Site знадобиться окрема конфігурація Next.js static export. [Next.js на Render](https://render.com/docs/deploy-nextjs-app) · [Типи сервісів](https://render.com/docs/service-types)

## Бюджет

Перевірено 18.11.2026. На сторінці тарифів базовий платний compute 0.5 CPU / 512 MB для сервісу або worker вказано від 7 USD/місяць, PostgreSQL 0.1 CPU / 256 MB від 6 USD/місяць. Три такі процеси та БД дають орієнтир 27 USD/місяць за compute при безперервній роботі. Трафік, storage, план workspace й потужність для імпорту розраховуються окремо. Підбір розміру worker потребує вимірювання на реальному міському витягу. [Тарифи](https://render.com/pricing) · [Плани compute](https://render.com/docs/compute-plans)

Free Postgres має 1 GB, спливає через 30 днів і не має керованих резервних копій. Free web services можуть засинати. Файли локального диска сервісу зникають при redeploy. Для накопичувальної CRM вибрати paid Postgres або зовнішню постійну PostgreSQL із перевіреним відновленням. Локальний Docker volume слугує тільки для розробки. [Обмеження Free](https://render.com/docs/free)

## Порядок введення в експлуатацію у фазі 14

1. Закріпити регіон, бюджет, доступ до БД та серверні секрети в Environment Group. Зібрати Web/API/Worker із того самого commit і lock-файлу.
2. Після появи міграцій виконувати `prisma migrate deploy` **одним** контрольованим pre-deploy кроком API. При помилці зупинити реліз. Застосовувати зворотно сумісні міграції, перевірені на копії. [Deploys](https://render.com/docs/deploys)
3. Додати `/api/v1/health/live` і `/api/v1/health/ready` з перевіркою БД після фази 3, точний CORS allowlist, HTTPS, приватні маршрути й контроль доступу до файлів. Перевірити drain активних jobs при SIGTERM.
4. Увімкнути щоденні резервні копії й моніторинг місткості, віку копії, черги та API-квот. Відновити копію в окрему БД, застосувати актуальні відкликання ліцензій, звірити кількість філій, фактів, спостережень, CRM та аудит.
5. Виконати два різні повні тестові скани з ручною правкою між ними. Перезапустити сервіси, звірити UUID, історію й CRM, відтворити експорт за run. Зафіксувати час відновлення та допустиму втрату даних разом із власником. Заплановані скани та Cron можна додати за потреби.
