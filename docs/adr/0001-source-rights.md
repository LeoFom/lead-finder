# ADR 0001 · Дозвіл на операцію для кожного факту

**Статус** Прийнято у фазі 0.

Один бізнес може мати назву з геоданих, телефон із власного сайту і ручний висновок про збіг на Maps. Прапорець на рівні всього бізнесу дозволив би перенести обмеження або права з одного поля на інше.

**Рішення.** Зберігаємо походження кожного внеску. Довірений адаптер або авторизований ручний маршрут встановлює джерело. Публічний API не приймає від клієнта grants чи готові ознаки довіри. Центральна функція перевіряє належність джерела до дозволених типів, повноту походження, права факту та активний запис реєстру. В експорт допускаються тільки поля з обома дозволами. Відсутній, невідомий чи прострочений grant закриває відповідну операцію.

Реєстр є серверною конфігурацією. Для нового постачальника потрібен запис із конкретними полями, правами, строком, версією та перевіреними умовами з посиланням. У фазі 2 ці відомості прив’язуються до license_registry. У фазі 6 парсер зіставляє внески з реєстром до запису. Для обмежених даних у діагностиці залишаються код причини та лічильник без вихідного тексту.

**Відкликання.** Заблокувати grant і зупинити адаптер. Визначити залежні поля, версії, журнали, jobs та файли. Припинити видачу активних URL, очистити заборонені значення, відновити проєкції з незалежних доказів, зареєструвати очищення без payload. Після restore застосувати реєстр відкликань до відкриття доступу. Архівні копії й строки їх ротації мають відповідати умовам постачальника. Ручні CRM-дії з власним походженням лишаються доступними.

**Наслідок.** До перегляду прав частина потенційних контактів відсутня. Повторна перевірка перед експортом дозволяє врахувати зміну умов після імпорту. Тести містять відхилення Google, Brave, невідомих прав, простроченого дозволу, змішаного походження та окремого обмеження експорту.
