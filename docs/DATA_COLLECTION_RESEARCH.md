# Збір інтернет-даних для Lead Finder

Дата перевірки: 19.11.2026. Статус: дослідження перед реалізацією; адаптери, grants, збір і платні сервіси не ввімкнено.

## Висновок і межа етапу

Почати з одного адаптера Overture Places для Івано-Франківська та стоматологій, із перевіркою історії до додавання другого джерела. Далі підключати дозволені офіційні сайти, потім оцінювати додаткове покриття Foursquare OS Places. OSM — окреме рішення щодо ODbL. Місцеві каталоги підключати лише за підтверджених умов автоматичного отримання, збереження та експорту.

Це дослідження відповідає перевірці джерел у §16, фаза 0, і готує фази 5–8 та 12. Воно не означає завершення цих фаз. У поточному коді вже є ручна CRM, але пошуковий engine та зовнішні адаптери ще не реалізовані.

## Джерела та підключення

### Overture Maps Places — перший адаптер

Це відкриті GeoParquet-файли, а не REST-пошук бізнесів. Офіційний доступ — STAC → реліз → Places → файли на S3/Azure. DuckDB або Python-клієнт дозволяють відбирати потрібні географію та колонки. Для цього доступу не потрібен Google API key. [Cloud sources](https://docs.overturemaps.org/getting-data/cloud-sources/)

Прямим читанням метаданих підтверджено:

- STAC `latest`: `2026-11-18.0`;
- схема: `2.0.0`;
- колекція `place`: серед колонок є `names`, `addresses`, `basic_category`, `taxonomy`, `websites`, `socials`, `phones`, `emails`, `operating_status`, `sources`, `bbox`;
- у колекції `license: other`, тому один загальний дозвіл на весь набір призначати не можна.

Під час запуску потрібно зафіксувати конкретний release ID. Категорії читати зі схеми релізу: старі приклади з `categories.primary` не переносити без перевірки. Українські aliases зіставляються з версіонованим словником, а не лише з підрядком у назві. [Place schema](https://docs.overturemaps.org/schema/reference/places/place/) · [Places guide](https://docs.overturemaps.org/guides/places/)

Для внесків застосовуються різні ліцензії: CDLA-Permissive-2.0, Apache-2.0 для Foursquare, CC0 для AllThePlaces. Перевіряти всі `sources[]` та внески до конкретного поля; зберігати тексти ліцензій, потрібні NOTICE/атрибуцію й повідомлення про зміни. Неоднозначний внесок відкидати. Це не загальний дозвіл на інші теми Overture: наприклад, Divisions має інші ліцензійні умови. [Attribution and Licensing](https://docs.overturemaps.org/attribution/)

Послідовність підключення: отримати STAC-метадані → перевірити реліз і ліцензії → вибрати bbox міста → точний polygon-фільтр → категорії → нормалізація → source guard → порції імпорту. Просторовий фільтр зменшує читання, але не гарантує, що мережевий обсяг дорівнюватиме розміру кінцевого JSON. Пілот має виміряти час, пам’ять і трафік.

### Foursquare Open Source Places — додаткове покриття

OS-набір містить назву, координати, адресу, категорії та за наявності `tel`, `website`, `email`, `instagram`; також дати й ознаки якості. `date_created` не є датою відкриття бізнесу, а `date_closed` — підтвердженою реальною датою закриття. Для відкритого продукту наведена Apache-2.0. Не переносити цей дозвіл на платний Places API або інші продукти. [Схема OS Places](https://docs.foursquare.com/data-products/docs/places-os-data-schema)

Актуальний шлях доступу: акаунт у Places Portal → вибір Places/Categories/Deltas → токен → Iceberg-каталог. Офіційна документація позначає старий публічний S3-доступ як замінений; готові connection snippets надає портал. Не вигадувати REST endpoint або використовувати застарілий S3 glob. Перед активацією перевірити умови порталу, доступні релізи й ліцензійні матеріали саме завантаження. Токен — тільки серверний секрет. [Access FSQ OS Places](https://docs.foursquare.com/data-products/docs/access-fsq-os-places)

Overture вже включає внески Foursquare. Тому приріст унікальних філій слід вимірювати, а не підсумовувати кількість рядків. Два дзеркала одного доказу не стають двома незалежними підтвердженнями закриття.

### OpenStreetMap — опційне окреме джерело

Доступний регіональний `.osm.pbf` України з Geofabrik. Обробка поза web-процесом: Osmium/інший PBF-парсер → географія → медичні POI та контакти → нормалізація node/way/relation → ліцензійний guard. Потрібно перевірити версію тегів для стоматологій; відсутня назва або контакт не заповнюється здогадкою. [Ukraine extract](https://download.geofabrik.de/europe/ukraine.html)

Зберігання й поширення можливі за ODbL з атрибуцією. Вимоги до похідної бази, колективної бази та публічної видачі потребують окремого рішення. Саме розміщення OSM в окремій SQL-таблиці не доводить відсутність share-alike зобов’язань. Не припускати, що треба відкривати весь програмний код; ліцензійний предмет тут — дані. [OSM copyright](https://www.openstreetmap.org/copyright)

Публічний Nominatim забороняє систематичне отримання всіх POI в області; це не джерело масового пошуку стоматологій. Для нашого застосунку рекомендовані витяги, а не обхід міст запитами до публічного геокодера. Публічний Overpass також не закладати як необмежений production backend. [Nominatim policy](https://operations.osmfoundation.org/policies/nominatim/)

### Офіційні сайти бізнесів — уточнення сайтів і контактів

Кандидат URL надходить із дозволеного набору або незалежного ручного вводу. Після перевірки прав і умов домену: HTTP-запит головної, контактів, за потреби сторінки про компанію; аналіз JSON-LD `LocalBusiness`/`Organization`, `url`, `sameAs`, публічних бізнес-контактів. Зберігати мінімальні факти й доказ URL/дати, не копію повного сайту. [Schema.org LocalBusiness](https://schema.org/LocalBusiness)

`robots.txt` визначає поведінку crawler, але не замінює дозвіл на зберігання та експорт. Якщо умови використання невизначені, постійний запис блокується. Для старту — перевірений allowlist доменів, невеликі бюджети сторінок, User-Agent, timeout, backoff на 429/403. Не обходити CAPTCHA або логін. [Robots Exclusion Protocol](https://www.rfc-editor.org/rfc/rfc9309)

HTTP-клієнт потребує SSRF-захисту: тільки http/https і дозволені порти, перевірка IPv4/IPv6 та DNS, блокування private/link-local/metadata адрес, повторна перевірка кожного redirect, ліміт відповіді. Звірка адреси/назви/бренду потрібна і після успішного HTTP 200. Помилки доступу дають `error`/`unreachable`, а не «сайту немає».

### AllThePlaces та Wikidata — резервні відкриті джерела

AllThePlaces публікує щотижневі gzipped NDJSON з GeoJSON features під CC0; код spiders має окрему MIT-ліцензію. Підключення — офіційні Downloads, вибір релевантних spiders, потокова фільтрація країни/міста. Це кандидат для мереж зі сторінками локацій; покриття локальних стоматологій треба виміряти. Його внески вже є в Overture, тому спершу оцінити дублювання. [AllThePlaces](https://alltheplaces.xyz/)

Структуровані дані Wikidata мають CC0. Можливе допоміжне зіставлення брендів та офіційних URL через обмежені SPARQL-запити або витяги. Права на тексти інших просторів Wikidata відрізняються. Для повного пошуку малих місцевих бізнесів цей варіант не обирається без пілота покриття. [Wikidata licensing](https://www.wikidata.org/wiki/Wikidata:Licensing)

### МОЗ України — окреме доповнення для медичної ніші

МОЗ публікує ліцензійний реєстр медичної практики, зокрема посилання на XLSX; у переглянутій сторінці зазначено актуальний перелік на 11.11.2026. Отримувати саме офіційний файл, не скрейпити Power BI або внутрішні endpoint. До підключення перевірити склад колонок, паспорт набору, права повторного використання, дату й обмеження персональних даних. XLSX у цьому дослідженні не завантажувався. [Ліцензійний реєстр МОЗ](https://moz.gov.ua/uk/licenzijnij-reyestr)

Реєстр допомагає перевіряти ліцензіата; юридична особа/ФОП не тотожна фізичній філії або торговельній назві клініки. Ліцензія не підтверджує роботу конкретної філії сьогодні й не надає сайту чи Instagram автоматично. Державну публічність не прирівнювати до дозволу накопичувати персональні контакти для розсилки.

## Потік даних та збереження історії

Запропонований контракт: адаптер повертає мінімальні факти з `sourceType`, `dataset`, `releaseId`, `externalId`, полем, усіма contributor refs, ліцензією, observed/verified timestamps та confidence. Дозволи визначає довірений реєстр сервера/підготовки набору. API не приймає клієнтський прапорець «дозволено» як доказ.

1. До запуску зафіксувати місто, перевірену геометрію, версію меж і таксономії, джерела, maxRecords, час і бюджет.
2. Перевіряти `requireSourceRights` до будь-якої довговічної черги, кешу, факту, історії або файлу. Невідомі внески відхиляти; у діагностиці — коди та лічильники.
3. За `sourceType + externalId` знаходити зв’язок із внутрішнім UUID філії. Сильні композитні збіги перевіряти окремо; нечіткі — на розгляд. Мережевий домен не є підставою зливати адреси.
4. У транзакції додавати новий доказ/версію, observation, подію та checkpoint з ідемпотентними ключами. Ручні facts/locks залишаються поточними, імпорт стає пропозицією. CRM та opt-out ізольовані від імпорту.
5. Missing фіналізувати лише для повного нового порівнянного знімка конкретного джерела. Ліміт рядків, уривання, відсутній пакет міста або помилка — `partial`/`failed`/`unavailable`, не повна порожня видача.
6. Повторно перевіряти права перед CSV/XLSX, додавати metadata та ліцензійні матеріали. Механізм відкликання очищає залежні докази й файли, але зберігає незалежні ручні дані.

## Безкоштовний старт та робота без БД

Render Free засинає після простою, має тимчасову файлову систему і не надає Free для всіх типів сервісів. Великий Parquet-імпорт не слід виконувати в одному HTTP-запиті поточного API або намагатися зберігати його результат у локальному SQLite Render. Перехід з NestJS на native Node.js не скасує ці обмеження. [Render Free](https://render.com/docs/free)

Пропозиція для обмеженого пілота:

- Підготовка Overture поза web-процесом: ручний запуск у Codespaces або окремий контрольований CI-job. Застосувати часовий/ресурсний ліміт і не відкривати анонімний trigger довільних запитів. Точний нуль витрат не гарантується: перевіряються квоти compute, storage і bandwidth.
- Вихід — компактний версіонований пакет відкритих фактів міста з manifest: реліз, schemaVersion, boundary/taxonomy version, coverage, дата підготовки, digest, поля та ліцензії. Публічна видача дозволена лише за окремо перевіреного права на розповсюдження всіх включених даних.
- Нормалізовані пакети можна доставляти як build-артефакти існуючого frontend-hosting, без CRM-БД і без Render API в шляху читання. Не комітити реальні контакти, raw payload або експорти в публічний Git-репозиторій. Жодні приватні нотатки/акаунти до пакета не потрапляють.
- Гість шукає у доступних пакетах і зберігає власну CRM локально. Потрібні новий формат provenance та повторна перевірка дозволів перед локальним збереженням/експортом. Пакети й правила походять із довіреної підготовки, не із довільного JSON користувача.
- За недоступної БД пошук у доставлених наборах працює. За недоступного Render він теж може працювати. Живий запит до бізнес-сайту потребує доступного серверного fetcher й інтернету: прямий браузерний crawling не є надійною заміною через CORS та секрети.
- Без інтернету доступні тільки заздалегідь завантажені дозволені дані. Для обмежених/прострочених прав експорт блокується; офлайн не можна обіцяти миттєву перевірку зовнішнього відкликання. Якщо потрібна гарантовано актуальна перевірка, операція потребує мережі.
- Коли БД повернеться, автоматичного заливання локальних CRM-правок немає. Синхронізація потребує окремого явного імпорту з переглядом конфліктів.

Для першої версії достатньо однієї погодженої географії. Міста без підготовленого набору мають явний стан «джерело недоступне», а не вигадану порожню базу. Після вимірювання навантаження можна вирішувати, чи потрібен worker та об’єктне сховище.

## Рекомендований наступний окремий етап

Спочатку реалізувати та прийняти engine і збереження спостережень/версій на синтетичних fixtures, включно з A/B/C, ручним lock і рестартом (§16, фази 5 та 7). Після готовності цього фундаменту — окремий вузький Overture-пілот (§16, фаза 6), без автоматичного переходу до другого джерела. Це враховує головний пріоритет власника: історія раніше за кількість адаптерів.

Критерії пілота: місто визначено однозначно; ліцензійні докази на поля повні; є реальні дозволені результати або чесно зафіксована відсутність покриття; повтор релізу не створює дубля/зміни/missing; ручна CRM збережена; неповний збір не збільшує missing; CSV має правильні джерела; гостьовий пошук по підготовленому набору витримує недоступність БД/API. Перевірити AC-03–13, AC-18–22. Окремо виміряти унікальні філії, заповненість адрес/сайтів/Instagram/телефонів, вік доказів, false matches, час і трафік.

## Перевірки цього дослідження

Прочитано ТЗ, PRD, архітектуру, реєстр джерел і ADR; переглянуто поточні schema, policy guard, gateway та ручні API-маршрути. Первинні вебджерела наведені поруч із висновками. Виконано лише читання невеликих STAC JSON-метаданих; бізнес-рядки, XLSX МОЗ і великі набори не завантажувалися. Акаунт Foursquare не створювався; портал із токеном не тестувався. Дозвіл Top20/List не підтверджений, автоматичний збір Locator заборонений його переглянутими умовами.

Код, схема БД і production у цьому етапі не змінювалися. Runtime-тести та CI для документаційного дослідження не запускалися; попередні успішні перевірки не видаються за перевірку майбутнього імпорту.
