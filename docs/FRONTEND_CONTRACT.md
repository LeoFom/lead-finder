# Інтерфейс і контракт NestJS

За рішенням власника від 18.11.2026 наступний етап виконує UI на mock-даних. Реалізація NestJS, міграцій та реальних джерел продовжиться після погодження інтерфейсу.

## Робочий прототип

Головний екран об’єднує профіль пошуку, статистику, фільтри, сортування, вибір рядків, CSV та картку бізнесу. Навігація відкриває CRM, історію і запуски. У CRM доступні статус, пріоритет, нотатка та ручний сайт із lock. Кожне місто й нормалізований запит мають окремий набір даних.

Знімок A містить вісім вигаданих бізнесів. Оновлення B додає дев’ятий, змінює сайт і позначає одну філію missing_once. Оновлення C повертає її зі станом reappeared. Подальші оновлення C ідемпотентні. Ручні дані переживають усі оновлення. Домени .example і назви є синтетичними. Instagram показується як текст. Автоматичного доступу до постачальників немає.

Сховище demo-v1 у localStorage зберігає роботу в поточному браузері. Власник може очистити його через дані сайту. Сховище має окремий ключ і версію. Для прототипу дані між вкладками та пристроями синхронізуються лише після повторного читання в тій самій вкладці. Остаточну валідацію DTO та авторизацію забезпечить сервер.

## Межа взаємодії

Компоненти викликають LeadGateway, реалізація demoGateway ізольована в lib/gateway.ts. Помилки показуються в UI. Під час заміни адаптера на HTTP змінити повернення повного демостанy на адресні React-запити з інвалідацією кешу.

| Дія              | Майбутній контракт                                               | Правило                                                                                               |
| ---------------- | ---------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------- |
| Відкрити профіль | POST /api/v1/search-profiles, GET /api/v1/businesses?profileId=… | Сервер повертає UUID, канонічний scope, cursor і total. Початкові UA, Івано-Франківськ, Стоматологія. |
| Таблиця          | GET /api/v1/businesses з filter, sort, cursor, limit             | Фільтри і пагінація на сервері. Вибір прив’язаний до UUID і поточної області.                         |
| Картка і журнал  | GET /api/v1/businesses/:id, GET /api/v1/businesses/:id/history   | Значення разом із джерелом, часом, confidence і license.                                              |
| Змінити CRM      | PATCH /api/v1/businesses/:id/crm                                 | status, priority, notes, followup, doNotContact. Версія або If-Match проти втрати конкурентних змін.  |
| Ручний сайт      | PATCH /api/v1/businesses/:id                                     | Самостійна команда з is_locked та аудитом, атомарна перевірка версії.                                 |
| Оновити пошук    | POST /api/v1/search-runs                                         | Idempotency-Key, 202, runId і Location. Polling до completed/partial/failed/cancelled.                |
| Зміни            | GET /api/v1/changes?profileId=…                                  | Події по UUID, run, джерелу і scope. Відсутність має окремий вимір від operating_status.              |
| CSV/XLSX         | POST /api/v1/exports, GET /api/v1/exports/:id/download           | Scope, фільтри, selected IDs, runId. Повторна перевірка прав кожного поля, metadata та TTL.           |

У HTTP-адаптері credentials включають сесію, CSRF застосовується до команд. Помилка має code, message, fieldErrors та requestId. 401 відкриває вхід, 409 пропонує перечитати свіжу версію, 429 повідомляє про ліміт. Перервана мережа не вважається успішним збереженням. Повторні спроби команд використовують той самий idempotency key.

Mock CSV містить UTF-8 BOM, поточну вибірку і атрибуцію в кожному рядку. XLSX, авторизація, Maps-check, масові дії CRM та серверні експорти залишаються окремими наступними кроками інтерфейсу. Сторінки поточного прототипу перемикаються в межах одного workspace.
